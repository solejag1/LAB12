## Объяснение от ИИ

### Что делает функция?

`calculate_commission()` рассчитывает итоговую комиссию за банковский перевод. На входе: сессия БД, ID счёта, сумма перевода и промокод. На выходе: объект `CommissionResult` с полной разбивкой: базовая комиссия, скидка, надбавка, итог.

### Разбор по шагам

**Шаг 1 — Валидация суммы**
```python
if amount <= Decimal("0.00"):
    raise HTTPException(status_code=400, detail="Amount must be positive")
```
Первый барьер: сумма ≤ 0 не имеет смысла. Это лучше поймать как можно раньше, до обращения к БД — дёшево и быстро.

**Шаг 2 — Загрузка счёта из БД**
```python
account = await _get_account(db, account_id)
```
Вынесено в отдельную `_get_account()` — принцип единственной ответственности. Если счёт не найден, функция выбросит 404, и до расчёта дело не дойдёт.

**Шаг 3 — Базовая комиссия**
```python
base = _calculate_base_commission(amount)
```
Простое умножение `amount × 0.03`, но через именованную константу `BASE_COMMISSION_RATE`. Если ставка изменится — меняем в одном месте.

**Шаг 4 — Промоскидка**
```python
after_promo, promo_discount = _apply_promo_discount(base, promo_code)
```
Словарь `PROMO_DISCOUNTS` с размерами скидок. Возвращает кортеж (новая комиссия, размер скидки) — это позволяет сохранить скидку для отчёта.

**Шаг 5 — Скидка за тип счёта**
```python
after_type, type_discount = _apply_account_type_discount(after_promo, account.account_type)
```
Сберегательные и кредитные счета получают дополнительные 5%. Скидки складываются — они не исключают друг друга.

**Шаг 6 — Надбавка за крупные суммы**
```python
surcharge = _calculate_surcharge(amount)
```
Переводы выше 1 млн или 500 тыс рублей получают фиксированную надбавку. Это типичная банковская практика для покрытия операционных расходов.

**Шаг 7 — Верификация внешним сервисом (best-effort)**
```python
async with httpx.AsyncClient(timeout=5.0) as http:
    await http.get(COMMISSION_SERVICE_URL, ...)
```
Ключевые решения здесь:
- `httpx.AsyncClient` вместо `requests.get` — не блокирует event loop
- `timeout=5.0` — не будем ждать вечно
- `try/except httpx.RequestError` — внешний сервис недоступен? Ничего страшного, транзакция всё равно проходит. Верификация best-effort.

**Шаг 8 — Возврат результата**
```python
return CommissionResult(
    base_commission=base,
    discount_applied=total_discount,
    surcharge=surcharge,
    final_commission=final,
    promo_code=promo_code,
)
```
`CommissionResult` — `dataclass(frozen=True)`. Frozen означает что объект неизменяем после создания — гарантия что никто не подправит результат расчёта случайно.

### Почему `Decimal`, а не `float`?

```python
>>> 0.1 + 0.2
0.30000000000000004   # ← float
>>> Decimal("0.1") + Decimal("0.2")
Decimal("0.3")        # ← точно
```

В банковской системе ошибка в 0.000000000000004 рубля на миллионах операций превращается в реальные деньги. `Decimal` гарантирует точную арифметику.

---

### Почему `Final`?

```python
BASE_COMMISSION_RATE: Final[Decimal] = Decimal("0.03")
```

`Final` — сигнал для людей и IDE: «это константа, не меняй её». Если кто-то попытается написать `BASE_COMMISSION_RATE = Decimal("0.05")` — mypy выдаст ошибку.
